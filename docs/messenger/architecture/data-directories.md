# Папки данных и несколько аккаунтов

[Маршрутизация чтения](../../README.md) · [Хранилище](storage.md) · [Shutdown](shutdown.md)

Каждая папка данных — независимые `messenger.db`, профили подключения, история,
настройки и резервные копии. Это локальные рабочие пространства, не сетевые аккаунты.
Без параметров используется прежняя стандартная папка; существующие данные не
переносятся и не копируются. Новая папка начинает с пустого хранилища.

Приоритет: `--data-dir <путь>` → `MESHCORE_DATA_DIR` → стандартная папка ОС.
Относительные пути считаются от текущей рабочей папки процесса и нормализуются
в абсолютные. `~` само приложение **не разворачивает**; используйте абсолютный путь
или `$HOME` в shell. Пустая переменная окружения игнорируется; отсутствующий/пустой
аргумент и повторный `--data-dir` — ошибка. Выбора через UI и «последней папки» нет.
Для нестандартной папки её имя отображается в заголовке окна.

## Запуск

macOS, установленный app bundle (имя/путь приложения уточнить по месту установки):

```sh
open -n -a MeshCoreMessenger --args --data-dir "$HOME/Library/Application Support/MeshCoreMessenger-Work"
open -n -a MeshCoreMessenger --args --data-dir "$HOME/Library/Application Support/MeshCoreMessenger-Personal"
```

`-n` нужен, чтобы macOS запустила новый процесс вместо активации существующего.
При запуске из репозитория, в отдельных терминалах после Release build:

```sh
dotnet src/MeshCoreMessenger.Desktop/bin/Release/net10.0/MeshCoreMessenger.Desktop.dll --data-dir /tmp/MeshCoreMessenger-Work
dotnet src/MeshCoreMessenger.Desktop/bin/Release/net10.0/MeshCoreMessenger.Desktop.dll --data-dir /tmp/MeshCoreMessenger-Personal
```

Альтернативно задать `MESHCORE_DATA_DIR` в окружении процесса. Папка создаётся при
старте; файл вместо папки или невозможность создания/записи дают понятную диагностику
в stderr и код `3`. Вторая блокировка той же папки даёт код `2`, до открытия БД/UI.
Блокировка удерживается до окончания штатного shutdown и закрытия хранилища;
постоянный lock-файл не мешает следующему запуску после освобождения handle.

**Разные папки не разрешают совместное использование serial-порта:** два экземпляра
не должны подключаться к одной USB-ноде одновременно. Для параллельных соединений
нужны разные порты/ноды; для проверки окон достаточно offline-режима.

## Проверки реализации

Детерминированные Desktop-тесты проверяют приоритет источников, нормализацию,
неразворачивание `~`, фабрику путей, заголовок, одновременные блокировки разных
каталогов и отказ второй блокировки той же (включая эквивалентный путь).
Startup-тесты проверяют код `3` для файла и недоступного каталога; тест Unix permissions
проверяет read-only каталог даже при ранее созданном writable lock-файле.
Release build: 0 предупреждений/ошибок. Регрессии: Desktop 132/132, Core 127/127,
MeshCoreSharp 92/92; `git diff --check` и локальные ссылки документации проверены.

Ручная UI-приёмка: открыть два окна с разными папками, проверить заголовки и
независимость настроек; запуск с занятой папкой должен отказать без нового окна.
После штатного закрытия эта папка должна открываться снова. Без параметров должны
открываться прежние данные. Пользователь подтвердил успешную ручную проверку
02.10.2026 («все ОК»); агент самостоятельно визуальную проверку не выполнял.
