# MeshCore Messenger — первая локальная итерация

Для переписки через одну MeshCore Companion ноду по USB Serial или TCP.
Контакты, каналы, имя и радиопараметры предварительно настраиваются на ноде
другим приложением. Управление контактами/каналами в этой итерации не подключено.

## Запуск

На текущем Mac можно открыть собранный `MeshCoreMessenger.app` или распаковать
`MeshCoreMessenger-osx-arm64.zip` и скопировать приложение в удобную папку.
Пакет self-contained: установленный .NET SDK/runtime для запуска не требуется.
Локальная ad-hoc подпись не является Developer ID/notarization для распространения.
Проверена сборка Apple Silicon; Windows и Intel Mac здесь не проверены.

Повторное открытие приложения с той же папкой данных показывает уже работающее
окно, включая восстановление из свёрнутого состояния. Второго подключения к ноде
не создаётся. Если приложение ещё запускается, возврат в окно может занять несколько
секунд. При ошибке активации не удаляйте lock-файл у работающего приложения.
Системный трей пока не включён: крестик по-прежнему выполняет штатное завершение.

Сборка из репозитория на macOS с .NET SDK:

```sh
bash tools/publish-macos.sh
```

Скрипт печатает путь к `.app` и `.zip` в `artifacts/macos/osx-arm64/build.*/`.
Каждый запуск сборки создаёт отдельную папку; предыдущий пакет не удаляется.
Для Intel можно указать `osx-x64`, но проверка запуска на Intel ещё требуется.
Без упаковки сохраняется прежний запуск:

```sh
dotnet run --project src/MeshCoreMessenger.Desktop -c Release
```

## Подключение

1. Откройте «Подключение», создайте/выберите профиль, сохраните его.
2. Для Serial укажите порт ноды (на проверенном Mac `/dev/cu.usbserial-0001`),
   скорость 115200. Для проверенного Heltec V3 используется DTR=true/RTS=true.
   Для TCP задайте адрес и порт Companion.
3. Подключитесь. При желании включите автоподключение/reconnect в профиле.
4. Дождитесь Online и загрузки справочника. История доступна и offline.

Нода определяется по полному собственному ключу, а не адресу/имени профиля.
При подключении другой ноды истории не объединяются. Одновременно управлять
одной нодой из двух приложений не следует. После изменения справочника или каналов
сторонним приложением переподключитесь, чтобы получить свежий snapshot.

## Переписка

- Выберите публичный или приватный чат, введите текст, нажмите отправку/Enter.
  Shift+Enter добавляет строку. Во время IME composition Enter не отправляет.
- Под полем видны UTF-8 байты и причины недоступности отправки. Для ЛС лимит
  160 байт; для канала меньше на размер имени отправителя и разделителя `: `.
  Кириллица/emoji могут занимать несколько байт. Превышение лимита сейчас
  блокирует отправку; автоматическое обрезание — будущая доработка.
- При offline или отсутствии контакта на ноде можно продолжать черновик.
  Отправка при коллизии шестибайтового префикса блокируется.
- Поиск доступен в поле над историей; кнопка со стрелкой вниз возвращает
  к актуальному концу переписки.
- В меню переписки доступны карточка контакта/канала и очистка локальной истории.
  Для ЛС также доступен сброс маршрута; это меняет его на flood для следующих TX.

## Статусы и повторы

Канальное принятие нодой не подтверждает получение всеми участниками.
В ЛС Delivered означает полученный соответствующий ACK. Unconfirmed/«Ошибка»
после ожидания ACK не доказывает, что адресат не получил текст; поздний ACK
может позже сменить статус на Delivered.

Автоповторы ЛС: до трёх flood-попыток; для известного маршрута до трёх known,
затем сброс и до двух flood. Итог показывается у одного пузырька. ACK останавливает
оставшиеся попытки. После перехода на новый timestamp адресат может увидеть дубликат.

ПКМ исходящего сообщения:

- Публичное «Повторить доставку» — прежний timestamp, тот же локальный пузырёк.
- Публичное «Отправить как новое» — новый timestamp и второй локальный пузырёк.
- ЛС Failed/Unconfirmed → «Отправить еще раз» — новый цикл и второй пузырёк.
  Исходное сообщение и текущий draft сохраняются.

После сбоя Unknown означает неопределённый результат. Автоматической отправки
на старте/reconnect нет. Для Unknown/Prepared приватное меню повтора пока скрыто;
можно осознанно скопировать текст и отправить новое сообщение с риском дубликата.

В карточке «О контакте» есть время ACK по часам ПК и история маршрутов.
Снимок configured route не является трассировкой реального радио-пути;
неоднозначные candidates отображаются без выбора выдуманного маршрута.
Очистка приватной переписки удаляет также delivery analytics этого контакта
на выбранной ноде, но сохраняет сам контакт и черновик.

## Данные и резервная копия

Стандартная папка на macOS:

```text
~/Library/Application Support/MeshCoreMessenger
```

На Windows — `%LOCALAPPDATA%\MeshCoreMessenger`. В папке находятся `messenger.db`,
профили, настройки и `Backups` (включая backup перед миграциями).
Файл данных не зависит от расположения `.app`; замена пакета не требует удаления БД.

Для простой ручной копии штатно закройте приложение и дождитесь завершения процесса,
затем скопируйте всю папку данных в отдельное место. Для восстановления при закрытом
приложении сохраните текущую папку отдельно и верните копию на прежнее место.
Не копируйте один работающий `messenger.db`: SQLite может иметь актуальные данные
в WAL. Для online backup существует Core API, но отдельной кнопки в UI пока нет.
При ошибке сохранения приложение предлагает восстановить запись; принудительный
выход может потерять ещё не сохранённые изменения.

Для изолированной проверки можно запускать с `--data-dir <полный путь>`;
см. [папки данных](architecture/data-directories.md). Восстановление старой копии
возвращает старую локальную историю и состояние, но не передаёт сообщения автоматически.

[Результаты проверки](../testing/first-iteration-closure.md) отдельно отмечают,
что проверено на текущем Mac/ноде и что осталось для аппаратной приёмки.
