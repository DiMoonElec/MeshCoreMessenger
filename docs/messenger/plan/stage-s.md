## Код и место в плане

**S — System / интеграция с ОС** — самостоятельная ветка прикладного плана.
A–F заняты основными стадиями, UI — компонентной переработкой, P — повторами ЛС.
T не выбран: T1/T2 уже обозначают wire timestamps в документации отправки.
Префикс S не зависит от очередности завершения D/E/F и не перенумеровывает их.

Номера S1–S7 задают устойчивые ссылки и рекомендованный порядок, а не обязательную
линейную очередь. Выбирать следующий шаг по его зависимостям и запросу пользователя.
Выполнение S не объявляет завершёнными Stage D, E или всю первую версию.

## Исходное состояние

Исходный checkpoint до S1; реализация и актуальный запуск описаны в [S1](s1-instance-activation.md).

- `Program` выбирает папку данных, захватывает `ApplicationInstanceLock` до открытия
  SQLite и удерживает его до закрытия хранилища. Занятая папка сейчас даёт exit 2.
- Один экземпляр на папку данных; разные `--data-dir` работают независимо.
  [Контракт папок и запуска](../architecture/data-directories.md).
- `MainWindow.OnClosing` запускает `DesktopShutdownCoordinator`; настоящий выход
  ждёт durable barriers, ошибка сохранения оставляет возможность повторить shutdown.
  [Контракт завершения](../architecture/shutdown.md), [B7.3](b7-3-shutdown.md).
- `DesktopPreferences` хранит тему и геометрию через `ISettingsStore`; отдельный
  `ApplicationSettingsView` уже существует. [C9](c9-preferences.md).
- `IMessageCommitNotifications` передаёт событие `MessageIngestor` после commit.
  `StoredIncomingMessage.Inserted` отличает новую запись от распознанного дубликата;
  событие не содержит текста, типа переписки и контекста начального drain.
- Public/Private workspace уже сохраняют независимые selection/history/draft owners.
  [Контракт workspace](chat-workspaces.md).
- Автоподключение и reconnect реализованы. Их policy и state machine не менять.

## Общие границы

Работа преимущественно в Desktop: Platform/Lifecycle, preferences, DI и существующие
views. Новые имена сервисов в подэтапах — предложения, не существующий API.
Допустимо небольшое аддитивное расширение Core DTO/read API для уведомлений,
если существующих данных недостаточно. Без новых проектов и большой переработки.

Скрытие окна не завершает UI owners, соединение, приём или запись истории.
Настоящий выход использует существующий shutdown и порядок освобождения БД/лока.
Показ окна из трея, повторного запуска и уведомления использует одно действие.
Показ/активация не вызывает connect, radio replay или изменение конфигурации ноды.
MeshCoreSharp остаётся свободной от UI, IPC, БД и системных уведомлений.

## Простое поведение для пользователя

- Сворачивание скрывает окно в трей. Крестик по умолчанию делает то же;
  второй вариант настройки — «Закрывать приложение».
- В меню трея только «Открыть» и «Выйти». Явный выход не зависит от настройки крестика.
- Два чекбокса: уведомления для личных сообщений и для каналов. Рекомендуемые
  значения для новой установки — оба включены; дополнительных фильтров нет.
- Уведомление показывает контакт/канал и короткий текст; просмотренное в активной
  переписке сообщение не требует баннера. Клик показывает соответствующую переписку.
- Несколько входящих подряд объединяются по переписке. Начальная очередь ноды
  после подключения даёт сводку вместо отдельного баннера на каждую запись.
- Ни показ баннера, ни клик сами по себе не меняют unread: действует прежний
  механизм фактического просмотра. Для нетекстовых данных — нейтральная подпись.

## Риски и обязательные проверки

Ранний повторный запуск до готовности UI, запуск во время shutdown, crash/stale IPC,
эквивалентные пути и разные папки; ограничения foreground activation и macOS reopen;
недоступный трей; hidden/minimized viewport и unread; ошибка сохранения при выходе
из скрытого окна; разрешения ОС, упаковка, delayed commits, drain/reconnect bursts,
распознанные дубликаты и устаревшая цель уведомления.

Гарантия single-instance — отсутствие второго полноценного экземпляра для той же
папки. ОС может создать кратковременный процесс повторного запуска: он передаёт
активацию и завершается до БД/DI/соединения. IPC не заменяет защитный файл-лок.
