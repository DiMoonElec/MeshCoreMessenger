## Шаги

1. При принятии job зафиксировать scope ноды и применять тот же snapshot во всех попытках, включая known→flood.
2. Сохранить существующие timestamp/attempt numbering, ACK grouping и stop-on-delivery; сообщения не дублируются из-за cleanup failure.
3. На legacy firmware сохранить документированный legacy path с Unknown provenance; не объявлять точный region snapshot там, где он недоступен. Per-contact policy не добавлять.

**За границами шага:** Per-contact GUI, новый retry алгоритм и гарантии scope автоматического ACK получателя.

## Проверки и завершение

**Обязательные проверки:** Direct и flood cycles; default изменён между попытками; late ACK останавливает job; scope SET failure; disconnect; старое устройство; сохранение существующего лимита попыток.

**Готово:** Регион не меняется незаметно внутри воспроизводимого цикла; legacy поведение не ломается.

Если зависимость отсутствует или проверка не выполнена, записать точную причину и
оставить соответствующий пункт открытым. Для аппаратных/GUI проверок различать
автоматический результат, native просмотр и пользовательское подтверждение.
