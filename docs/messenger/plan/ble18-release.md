## Шаги

1. Выполнить существующую Windows self-contained упаковку, проверить одну MeshCoreSharp.dll и WinRT runtime dependencies. Запустить unpackaged EXE из ZIP без dev SDK, по возможности в чистом профиле/окружении.
2. Проверить именно unpackaged Bluetooth доступ и consent/pairing; не считать UWP manifest инструкцию доказательством работоспособности portable EXE.
3. Собрать и проверить macOS TCP/Serial, history и старт с сохранённым BLE-профилем: понятная unsupported ошибка без Windows assembly load failure. Если macOS нет — зафиксировать ожидающую native приёмку.
4. Обновить пользовательскую инструкцию: Windows support, pairing, выбор ноды, отключение другого клиента, причины ошибок и восстановление связи.
5. Обновить статус BLE и ссылки; README «BLE не поддерживается» заменить только после подтверждённой реализации. Указать протестированные firmware/платформы, не обещать все BLE-ноды.

**Не входит:** Поддержка BLE macOS/Linux, MSIX-only переход, новые автообновления.

## Проверки и завершение

**Тесты/проверки:** Locked restore/build, release artifact launch, BLE connect из поставляемого EXE, TCP/Serial smoke, macOS native regression; win-arm64 проверять только если заявляется поставка этой архитектуры.

**Готово:** Windows поставка проверена и описана, сохранность macOS подтверждена либо отдельный outstanding пункт явно препятствует полному закрытию BLE18.

**Ручная проверка:** Обязательна: Windows portable; macOS regression отдельным фактическим результатом.
