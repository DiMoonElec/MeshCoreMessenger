# Первая итерация — оценка минимального завершения

05.10.2026: доступные автономные завершающие работы выполнены; см.
[результаты и оставшиеся проверки](../../testing/first-iteration-closure.md).
Исходная оценка ниже сохранена как обоснование выбранного scope.

05.10.2026. Анализ по запросу пользователя: как быстрее завершить текущую
итерацию и пользоваться приложением для переписки. Ниже предложение сокращённой
приёмки, а не объявление всех Stage D/E завершёнными. Новые функции не реализованы.

## Минимальная цель

Личное использование на текущем Mac с заранее настроенной Companion нодой,
контактами и каналами: подключиться, читать/писать, видеть честные статусы,
перезапускать приложение без потери истории/черновиков и без replay исходящих.
Самостоятельное управление справочником/каналами и публичный cross-platform релиз
в эту минимальную цель не включаются.

## Что уже есть

- TCP/Serial profiles, подключение/reconnect, статус ноды, offline история,
  раздельные данные по полному ключу ноды, обработка suspend/resume в архитектуре.
- Public/private workspaces, списки контактов/устройств, поиск, bounded history,
  unread, draft, тема и сохранение положения окна.
- Канальная отправка, счётчик UTF-8 и валидация, два действия повторов.
- Личная отправка, точное ACK matching, late ACK, 3 flood или 3 known + 2 flood,
  FIFO по контакту, ручное «Отправить еще раз» с новым сообщением.
- Сброс и актуализация маршрута, карточки контакта/канала, delivery history,
  локальная очистка истории и scoped delivery analytics.
- Durable writes/recovery/shutdown и отсутствие автоматического TX при reconnect.
  Core backup/restore API и backup перед миграциями; отдельного пользовательского
  UI резервного копирования сейчас нет.

Последняя [приёмка P8](../../testing/private-retries-acceptance.md): Library 105/105,
Core 384/384, Desktop 328/328; native audits Light/Dark, narrow/wide. Это доказательство
автоматических сценариев, а не полной аппаратной/cross-platform приёмки.

## Минимум для завершения

1. Зафиксировать границу: заранее настроенные контакты/каналы, текущая платформа;
   не ждать D8–D13, Tools и нового contact UI для обычной переписки.
2. Короткая аппаратная проверка реального Desktop: двусторонний public/private
   обмен; повтор/late ACK; закрытие и reopen с draft/history; разрыв используемого
   TCP/Serial и reconnect; сон/пробуждение, заблокированный/погашенный дисплей.
   Проверить ожидаемый отказ и сохранность при доступном воспроизведении ошибки БД.
   Нативный crash -6661 диагностической утилиты отдельно описан в
   [startup investigation](../../testing/viewport-audit-startup.md); он не доказывает
   проверку production Desktop во всех состояниях дисплея.
3. По результатам исправлять воспроизводимые блокирующие баги. Дальняя multi-hop
   доставка пока не подтверждена: если она нужна для повседневной переписки,
   выполнить оставшиеся аппаратные сценарии P8; отсутствие ACK само по себе
   не устанавливает, что причина в приложении, а не радиопрохождении.
4. Короткая пользовательская инструкция: запуск/профиль, папка данных, безопасная
   резервная копия при закрытом приложении, восстановление, статусы/лимиты.
   Не предлагать копирование работающей SQLite DB без учёта WAL.
5. Убрать/отключить пустые test menu actions Search/Share/SetRoute для повседневной
   версии; работающий поиск в переписке сохранить. Это небольшой UI cleanup.
6. По потребности собрать стабильный запуск на текущем Mac. Если запуск через
   dotnet устраивает, упаковка не блокирует личную итерацию; для запуска без SDK
   понадобится self-contained пакет и его отдельная проверка. Windows/signing/
   notarization остаются обязательствами соответствующего будущего релиза.

## Явные ограничения этой итерации

- Добавление/редактирование/удаление контактов и изменение каналов выполняются
  вне приложения; после сторонних изменений нужно переподключиться для snapshot.
- Новый advert candidate UI и ручной self advert D16/D17 не подключены.
  Если адресаты уже знают ключ отправителя, ручной advert не обязателен для цели.
- Prepared/Unknown после сбоя не передаются автоматически. Приватный пункт
  «Отправить еще раз» доступен для Failed/Unconfirmed, но не Unknown/Prepared;
  при осознанном повторе такого текста пока можно скопировать и отправить новое.
  Возможный дубликат объяснить в инструкции, расширение recovery menu — отдельно.
- Детальная collision card не реализована; существующая защита и сообщение
  причины недоступности Send остаются. Системные уведомления/звук тоже отложены;
  для переписки при открытом окне они не обязательны.
- Оптимизация кириллицы, packet hashes/debug RX, инструменты, аналитические
  улучшения и [stress scroll](../../testing/known-ui-limitations.md) не блокируют
  обычную переписку в текущем текстовом лимите.

[Контактные идеи](contact-management-future-ideas.md) сохранены для следующего
обсуждения. Исходные [Stage D](stage-d.md), [Stage E](stage-e.md) и их требования
сохраняются: личная первая итерация с ограниченным scope не равна полному A–E релизу.
