# BLE17 — Аппаратная приёмка Windows BLE

[Stage BLE](stage-ble.md) · [Оглавление](../../MESSENGER_PLAN.md)

**Статус: запланирован 15.10.2026; реализация не начата.**

**Цель:** Подтвердить повседневную работу с выделенной нодой.

**Зависимости:** BLE8, BLE16. Проверить результаты зависимостей перед началом.
Общие инварианты и решения — в [Stage BLE](stage-ble.md).

**Файлы/область:** Приложение с отдельным временным data-dir; отчёт `docs/testing/ble17-hardware.md` создать при выполнении.
Новые имена/папки — предлагаемое место реализации; проверить актуальные исходники.

## Шаги

1. Зафиксировать ноду/прошивку/Windows/BT-драйвер/MTU и точный билд приложения; выполнить saved-profile connect/disconnect/reopen.
2. Проверить загрузку контактов/каналов, длинные ответы и входящий backlog. Использовать тестовую ноду: SYNC_NEXT_MESSAGE извлекает очередь, поэтому это уже не read-only probe BLE8.
3. Согласовать канал/контакт и текст с пометкой разработки перед RF-передачами. Проверить длинный исходящий текст, входящий ответ, приватный MSG_SENT и отдельный ACK, отсутствие автоматического replay от reconnect.
4. Проверить node off/on, Bluetooth off/on, out-of-range/возврат, sleep/wake, manual disconnect во время retry и закрытие приложения при pending open.
5. Проверить initial pairing, неверный PIN/нет pairing, повторный запуск со старой bond. Удаление bond выполнять только для выделенной ноды в согласованном сценарии; не очищать глобальные Windows Bluetooth настройки.

**Не входит:** Прошивка/сброс ноды, provisioning, перебор чужих устройств, обход сопряжения.

## Проверки и завершение

**Тесты/проверки:** Результат каждого сценария отдельно: passed/failed/not run с причиной. Сопоставить длинные кадры TX/RX, persistent history, отсутствие дубликатов/потерь; неподдержанную аппаратную разновидность не объявлять проверенной.

**Готово:** Есть подтверждённая Windows матрица; непроверенные пункты явно остаются открытыми. При дефекте исправление и focused regression предшествуют повторной проверке.

**Ручная проверка:** Обязательна; отсутствие ноды или получателя не заменяется fake результатом.

- [ ] Статус подэтапа, checklist Stage BLE и current-state обновлены.
