# D1 — UI отправки, исходящих и статусов

[Stage D](stage-d.md) · **Статус: выполнен. Автоматические проверки и визуальная
ручная приёмка пользователем подтверждены 03.10.2026.**

**Цель:** согласовать визуальный контракт до подключения эфира.

**Scope:** Composer с местом для UTF-8 счётчика/ошибок и Send; исходящий пузырь,
время и текстовые статусы Prepared/Sending/AwaitingAck/Delivered/AcceptedByNode/
Unconfirmed/Failed/Unknown. Просмотр попытки и явный повтор с предупреждением
дубликата. Preview показывает все состояния на тех же controls, без записей в БД.
Составной composer presentation owner использует существующий draft owner, не
переносит его сохранение в view. Два chat workspace остаются независимыми.

**Не входит:** настоящий подсчёт лимита, отправка, outgoing SQL, изменение Core/schema,
session API, замена history/scroll. Обычный Send остаётся выключенным с пояснением.
Макет счётчика — только demo; не дублировать encoder для production валидации.
**Зависимости/чтение:** [baseline/preview](stage-d-start.md), UI2, существующие
ComposerView/ConversationView/HistoryMessageListItem; sending architecture.

**Тесты:** runtime заглушка не вызывает client/store; preview всех статусов;
bindings/resources обеих тем; draft/copy/mentions/public-private round trip;
доступность кнопок, понятность статусов без одного лишь цвета.

**Готово:** воспроизводимый preview, компоненты готовы к D2/D5; обычный запуск
ничего не отправляет. В отчёте — команда preview и список demo-состояний.
**Ручная проверка: обязательна** — две темы, narrow/wide, длинные имена, текст/emoji,
пузыри, статусы, disabled Send и предупреждение повтора.

## Согласованный UI и результат

- Сохранена существующая кнопка отправки. Под полем слева единая строка:
  `42 / 160 байт - offline • Черновик не сохранён`. Исчезновение пояснений оставляет
  только счётчик. В D1 числа задаются только в preview; production не выдумывает
  бюджет до общего валидатора D2. Ввод длинного текста/Unicode не обрезается.
- `ComposerViewModel` композиционно использует прежний `DraftEditorViewModel`:
  сохранение/debounce/flush остаются у draft owner. Ошибки сохранения теперь видны
  в строке composer. Два workspace имеют независимые composer/draft owners.
- Общий `MessageView` используется в настоящей истории и preview. Входящие слева,
  исходящие справа; время перенесено под пузырёк. Там же форматтер выводит статус,
  номер попытки во время отправки, необязательные hops/число ретрансляторов.
  Production history пока имеет только достоверное время, без выдуманных метаданных.
- Ошибка — текст «Ошибка» и красный фон пузырька с отдельными Light/Dark токенами.
  Доставлено означает ACK, принято нодой не обещает доставку участникам канала.
- Контекстное меню сохраняет копирование исходного текста/mention syntax;
  добавлены «Сведения о сообщении» и «Повторить отправку». Видимость и доступность
  повтора задаются presentation отдельно. Подтверждение предупреждает о дубликате;
  после него повторно проверяется доступность захваченного сообщения.
  UI вызывает команду владельца, сам не вставляет сообщение в коллекцию.
- Root MainWindowViewModel, Core/schema, radio/session API не изменялись.
  Изменение размера строки истории проверено существующим viewport audit.
  Исправлен обнаруженный native audit binding рамки поиска: свойство теперь
  возвращает `Thickness`, а не несовместимый `double`.

## Изолированный preview

```sh
dotnet run --project tools/MeshCoreMessenger.SendUiPreview -c Debug
```

Отдельный host использует production MessageView/ComposerView/styles; не создаёт
Desktop composition root, paths/SQLite/session/client. Все данные только в памяти.
Счётчики и состояния явно обозначены как демонстрационные; выбор темы/чата не
открывает соединение. Кнопка Send выключена и в preview.

Личный чат содержит все восемь состояний. Канальный — Prepared/Sending/
AcceptedByNode/Failed/Unknown без Delivered. Обе вкладки содержат входящее с
примером hops; канальный — подписи ретрансляторов. Номер `3/5` демонстрационный:
автоматические повторы и фактическая доступность relay metadata здесь не определены.
Правила повторов по ACK/ретрансляторам требуют отдельного решения функциональных
подэтапов; текущий контракт сохраняет один wire-вызов на явное действие.

Unknown/Failed показывают доступный mock repeat; Unconfirmed в личном — видимый,
но выключенный пункт. Остальные скрывают пункт. Cancel не меняет состояние;
подтверждение mock repeat обновляет тот же объект/пузырёк до Sending и скрывает пункт.
Кнопки сверху демонстрируют несколько причин, ошибки и исчезновение пояснения.
Подробности: [README preview](../../../tools/MeshCoreMessenger.SendUiPreview/README.md).

## Ручная приёмка

03.10.2026 пользователь просмотрел preview и подтвердил: «по визуалу все устраивает».
Визуальный контракт D1 принят. Ниже сохранён сценарий проверки; это подтверждение
не утверждает отдельно прохождение каждого пункта или аппаратных испытаний.

1. Открыть preview, проверить Light/Dark и narrow/wide, перенос длинных имён,
   Cyrillic/emoji/mentions; подписи снаружи входящих/исходящих пузырьков.
2. Посмотреть восемь личных статусов и отдельный конечный AcceptedByNode канала;
   ошибка заметна текстом и красным фоном, пояснения доступны из меню.
3. Переключить кнопки пояснений: несколько причин разделены `•`, после исчезновения
   остаётся счётчик. Send выключен; Tab/клавиатура, ввод многострочного текста.
4. Проверить скрытый/disabled repeat, открыть доступный repeat, отменить, затем
   подтвердить: метаданные того же пузырька обновлены, нового сообщения нет.
5. Копирование сохраняет оригинальный текст и syntax упоминаний. Public/Private
   переключение сохраняет каждый введённый demo-черновик.
6. В обычном запуске проверить сохранение offline черновика и недоступность Send.
   Настоящий счётчик/валидация подключаются только D2; эфир в D1 не проверять.

D2–D18 не начаты.
