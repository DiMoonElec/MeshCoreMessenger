# P2 — durable подготовка личных повторов

05.10.2026. [Итоговый план](../messenger/plan/d7-private-auto-retry.md).
P1 закоммичен как `243077b`; этот отчёт описывает следующую часть P2.

## Реализация

SQLite v5 добавляет цикл доставки, сетевые идентичности и снимки попыток, общий
для ЛС собственной ноды timestamp floor и фундамент истории успешных доставок.
Перед upgrade создаётся backup v4. Legacy попытки сохраняются; floor получает
максимальный допустимый private timestamp. Маршрут и attempt старых отправок
не выдумываются: новые поля остаются NULL.

`BeginPrivateCycleAsync` фиксирует политику и бюджет 3/5 передач.
`PreparePrivateAttemptAsync` в одной writer-транзакции проверяет node/session/
контакт, предыдущую попытку и фазу; резервирует timestamp, сетевую идентичность
и неизменяемый снимок маршрута/времени. PreparationId делает повтор операции
идемпотентным. После commit публикуется уведомление; при rollback уведомления нет.
Подготовка не вызывает Companion API и не выполняет TX/reset.

Один MessageId/LocalSequence остаётся на весь цикл. Режим по умолчанию сохраняет
T1/0,1,2 и при fallback создаёт T2/0,1; другой режим резервирует timestamp на каждом
шаге с attempt 0. Новый timestamp больше предыдущего, даже при переводе часов
назад. PC UTC/offset/timezone записываются отдельно от сетевого времени.

После restart/restore активные циклы становятся Unknown/StartupRecovery без replay.
Очистка блокируется также между попытками активного цикла. Timestamp floor сохраняется
при очистке переписки; аналитические снимки сохраняются с NULL вместо ссылок на
удалённые сообщения/попытки. Восстановление старого backup возвращает БД, включая
floor, к сохранённому снимку; гарантия монотонности относится к текущей БД.

## Проверки

Release solution build: **0 warnings, 0 errors**. Core **303/303**, Desktop
**315/315**, библиотека **105/105**. Добавлен 21 тестовый случай:

- Оба режима × исходный flood/known: 3/5 попыток, одна история, правильные
  timestamp/attempt/фазы, UTC offset и timezone.
- Повтор и конкурентный повтор PreparationId не добавляют попытку и не расходуют
  второй timestamp; изменённые параметры, чужой node/session, неверная фаза,
  преждевременный переход и изменение зафиксированного timestamp отвергаются.
- Инъекция ошибки SQL откатывает reservation, снимок и progress без уведомления.
- Startup recovery для Prepared и завершённой тайм-аутом попытки; clock rollback,
  restart и очистка не уменьшают floor. Поздний ACK предыдущей попытки блокирует
  подготовку следующей. Cancellation и UInt32 overflow не создают capture.
- Upgrade v4, backup и legacy floor; ошибка миграции оставляет схему v4 и backup.
- Пять форматов route capture: flood, direct, 2/3-byte hop hashes; обрезание padding,
  копирование буфера, отклонение неполных/неподдерживаемых путей.
- Запрет очистки между попытками; сохранность history/evidence/candidates после
  очистки. SQLite foreign_key_check не выявляет нарушений.

Одна sandbox-сборка зависла после вывода библиотечного проекта; собственный процесс
остановлен. Повтор с `-m:1 -nr:false -p:UseSharedCompilation=false` успешно завершился.
Тесты TCP выполнялись вне sandbox с локальной эмуляцией; аппаратная нода не использовалась.

## Граница checkpoint

MessageService пока сохраняет прежнюю одноразовую отправку. P2 не подключает
автоматические повторы, не записывает успешную доставку в новые таблицы и не
меняет UI. Следующий P3 — общий ACK commit, итог сообщения и атомарная аналитика;
исполнение циклов и owned reset подключаются в P4/P5.
