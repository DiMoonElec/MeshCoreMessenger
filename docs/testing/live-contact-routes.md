# Актуализация маршрутов контактов — 04.10.2026

Исправлены два сценария: после обучения маршрута нодой UI обновляется без
переподключения; после ручного сброса читается один контакт вместо всего справочника.

## Контракт

- Библиотека декодирует `PATH_UPDATED`: `81 | full public key[32]` в публичный
  `PathUpdatedPacket`. Минимальная длина проверяется; расширения допускаются.
  ACK и PATH_UPDATED — независимые push; успешный ACK сам по себе не доказывает
  изменение маршрута и не содержит пути.
- `MeshCoreClient.GetContactAsync(fullKey, token)` отправляет `GET_CONTACT_BY_KEY (30)`
  и ждёт ContactPacket именно с этим полным ключом. Аргумент копируется до await,
  ERROR/timeout/cancellation и single-flight используют существующий dispatcher.
  Библиотека не инициирует дополнительные команды при push самостоятельно.
- Session копирует ключ только для PATH_UPDATED. Для остальных пакетов nullable
  ключ отсутствует, поэтому ACK и MessagesWaiting продолжают обрабатываться.
- ReceiveCoordinator ставит push-копии в отдельную session-owned очередь readback.
  Чтение начинается после начальной синхронизации; повторные уведомления одного
  ключа объединяются. Уведомление во время чтения оставляет ещё один запрос,
  чтобы окончательное изменение не потерялось. Event pump и RX не ждут этот запрос.
- Читается маршрут одного контакта, выполняется точечный UPDATE существующей
  локальной записи. Не добавляются контакты/сообщения и не изменяются каналы.
  NodeId и SessionId фиксированы; время наблюдения захватывается до чтения.
  Существующий RouteObservedUtc защищает от устаревшего readback после сброса.
- `ContactRouteCommitted` публикуется после commit. Desktop ставит обновление
  локальных projections в существующую очередь; обновляются заголовок переписки
  и карточка устройства. Смена выбранного чата не перенаправляет запись.
- Сброс выполняет ResetPath → GetContact → SQLite → UI, сохраняя прежний guard
  отправки/ACK и honest partial-success поведение. Fixed 2-second delay отсутствует;
  сокращено количество передаваемых контактных кадров. Очередь других команд и
  транспорт всё ещё могут влиять на задержку.
- При отключении background readback отменяется и завершается до закрытия session;
  подписка UI удаляется при Stop. Ошибка чтения не повторяет отправку или сброс,
  не вызывает reconnect сама по себе. Последняя ошибка доступна через
  ReceiveCoordinator.LastRouteRefreshError; новое уведомление позволяет обновить
  маршрут после устранения ошибки. До успешного readback отображается прежний кеш.

## Проверки

Solution Debug/Release: 0 предупреждений/ошибок. Library и Desktop runners — Debug,
Core runner — Debug и Release. `git diff --check` пройден.

- Library: 99/99. Два новых сценария: полноключевой запрос, копирование аргумента,
  unrelated push/чужой Contact, validation/cancellation/ERROR/timeout/recovery;
  PATH_UPDATED full-key/minimum-length/extensions.
- Core: 267/267. Пять новых TCP-сценариев: reset → flood → learned direct/2-byte
  route без reconnect, ровно один контакт для reset, отсутствие полного GetContacts,
  post-commit identity и сохранность другого контакта, burst во время заблокированного
  readback с поздним ACK, восстановление после ERROR, отмена при shutdown.
  Существующие SQLite проверки дополнены post-commit чтением, ошибочным subscriber
  и отсутствием уведомления при отклонении старого маршрута.
- Desktop: 306/306. Новый сценарий: смена flood → directly в заголовке по commit,
  фильтрация другой ноды, сохранность history owner/body/selection и unsubscribe.
- Использованы временные SQLite и loopback TCP. Аппаратная проверка ожидается.

Ручная приёмка: сбросить маршрут личного контакта, отправить flood-сообщение и
проверить новый маршрут в заголовке и карточке устройства без reconnect. Маршрут
может быть напрямую или через ретрансляторы; UI показывает фактический readback.
