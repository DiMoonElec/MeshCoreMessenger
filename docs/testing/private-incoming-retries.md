# P7 — входящие повторы ЛС и UI-проекции

05.10.2026. Реализована смысловая дедупликация обычных входящих ЛС в SQLite ingest.
Нода, однозначно разрешённый полный контакт, Plain, timestamp отправителя,
точный текст и дополнительный sender prefix определяют локальное сообщение.
SessionId, путь, SNR и время получения ПК не входят в эту идентичность. Attempt
не присутствует в ContactMessage Companion DTO: приём объединяется по доступной
идентичности сообщения, а не по packet hash. Протокольная библиотека не менялась.

Поиск выполняется после разрешения текущего полного ключа и внутри той же writer
транзакции, что сохранение. Найденный повтор возвращает исходные MessageId,
ConversationId и LocalSequence с Inserted=false и новым EventId. Новый пузырёк,
увеличение unread, обновление превью и scroll intent не создаются. Первые ReceivedUtc,
path/SNR остаются неизменными: отдельные radio observations и packet hashes отложены.

Точный текст сравнивается без trim, изменения регистра или нормализации Unicode.
Новый timestamp означает отдельное сообщение даже при одинаковом тексте; это
включает согласованный known T1 → fallback flood T2 и режим NewTimestampResetAttempt.
Строго одинаковые Plain/key/timestamp/text/extra нельзя отличить от повтора:
два намеренных сообщения с этой полной идентичностью также объединятся.
Объединение по одному тексту/временному окну не используется.

Unknown/ambiguous шестибайтовые префиксы не объединяются. После смены полного ключа
при прежнем префиксе новое событие относится к новому контакту. CLI, signed room
posts и публичные сообщения сохраняют прежнее поведение; их специальные правила
идентичности не подменяются алгоритмом обычных личных сообщений.

SQLite v6: IncomingMessageEvents(EventId PK, MessageId FK CASCADE) связывает все
события с каноническим сообщением. Миграция переносит первоначальные EventId, добавляет
частичный индекс private retry и сохраняет backup v5. Уже существующие сообщения,
их порядок, тексты и unread не переписываются; прежние дубли не удаляются задним числом.
Aliases записываются атомарно. Поэтому replay события после reopen или изменения
справочника возвращает прежнее сообщение. Ошибка alias write откатывает транзакцию,
ingress останавливается и восстанавливается через существующий SQL retry.

Очистка удаляет Messages и все их aliases каскадно. Сохранённого dedup tombstone
нет: пакет, полученный после очистки, может появиться снова. Очистка delivery/ACK
аналитики остаётся scoped и сохраняет timestamp floor, как реализовано ранее.

Исходящие UI projections уже используют итог PrivateDeliveryCycle перед последней
attempt: Prepared/Active → «Отправка», budget отображается под тем же пузырьком;
Unconfirmed/Failed → красная ошибка; Delivered остаётся приоритетным при позднем ACK
и cleanup последней attempt. Проверки расширены для всех итоговых состояний.
Счётчик composer остаётся 160 UTF-8 байт, не уменьшен для повторов.

При регрессионной проверке обнаружена зависимость доступности канальных повторов
от порядка Accepted publication и завершения composer command. Coordinator теперь
пересчитывает оба пункта при изменении SendCommand.IsRunning, с отпиской при Dispose.
Прежние два канальных действия, черновик, offline и запрет double-click проверены.

Проверки:

- одинаковая идентичность, разные сессии/path/SNR/ReceivedUtc → один message/sequence;
- повтор после прочтения не возвращает unread; новый timestamp увеличивает его;
- новый текст/регистр/пробел/extra и другой full key/node → отдельное сообщение;
- unknown/ambiguous, CLI/room/channel не объединяются;
- конкурентные события сериализуются в один message и отдельные event aliases;
- reopen и изменение справочника сохраняют техническую идемпотентность;
- v5 → v6, backfill, backup, legacy history, FK cascade при clear;
- отказ alias write → persistence pause/retry без второго пузырька;
- production TCP Companion drain: legacy и V3 получают три события T1/T1/T2,
  сохраняют два сообщения и два unread, без исходящих radio передач;
- Desktop real SQLite: повтор не создаёт pending/unread, новый timestamp создаёт
  второе сообщение; исходящие budgets/status priority и канальные повторы проходят.

Release build: 0 warnings/errors. Core 369/369, Desktop 327/327, Library 105/105.
Native GUI и аппаратные эксперименты в этой задаче не запускались. Следующий P8 —
