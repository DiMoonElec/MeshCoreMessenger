# BLE17 — аппаратная приёмка Windows BLE

16.10.2026. [Подэтап](../messenger/plan/ble17-hardware.md).
**Статус: частичная ручная приёмка; два сценария подтверждены пользователем.**

## Условия и источник результатов

Результаты ниже сообщил пользователь после проверки настоящего приложения по
BLE на Windows. Агент эти действия не выполнял, логи/точные задержки не снимались.
Ранее для этой ноды зафиксированы Heltec V3, firmware 1.18 и ATT MTU 176
([аппаратный отчёт](ble-stock-firmware.md)); заново в этих сценариях они не измерялись.
Точный билд запущенного приложения, версия Windows/BT-драйвера и использованный
data-dir отдельно не зафиксированы. Текущий HEAD перед записью отчёта — `6934094`;
это не доказательство версии запущенного бинарника.

## Подтверждённые сценарии

| Сценарий | Действия и наблюдаемый результат | Итог |
| --- | --- | --- |
| Sleep/wake с накоплением входящих | Подключиться к ноде по BLE → перевести ПК в сон → отправить на ноду 2 сообщения. На ноде появились непрочитанные. После пробуждения ПК приложение подгрузило сообщения. | Passed, подтверждено пользователем |
| Node power off/on и восстановление | Подключиться по BLE → отключить питание ноды. Через некоторое время приложение обнаружило потерю ноды и начало восстановление соединения. После подачи питания приложение восстановило подключение. | Passed, подтверждено пользователем |

Ранее пользователь также подтвердил GUI connect/sync и отправку ЛС/каналов;
результат записан отдельно в [BLE15](ble15-profile-ui.md#ручная-приёмка).

## Открытые проверки

Не заявляются пройденными на основании этих двух сценариев:

- Bluetooth adapter off/on, выход из зоны связи и возврат.
- Ручное отключение во время retry и закрытие приложения при pending open.
- Pairing без bond, неверный PIN и повторный запуск со старой bond по согласованному
  сценарию; существующее сопряжение не удалялось агентом.
- Точная фиксация окружения/билда, saved-profile disconnect/reopen на реальной ноде.
- Пограничные длинные RX174–176, сквозные пределы исходящего текста и сопоставление
  приватных MSG_SENT/ACK с сохранёнными статусами.
- Отсутствие дубликатов/потерь истории и автоматического replay при реальном reconnect
  отдельной сверкой. Успешное переподключение само по себе этого не доказывает.

BLE17 целиком не закрыт; BLE8 RX174–176 и оставшиеся ручные пункты BLE15 открыты.
Изменений кода, повторной отправки, чтения очереди или изменения конфигурации ноды
агент при записи отчёта не выполнял. Автоматические тесты для изменения документации
не запускались.
