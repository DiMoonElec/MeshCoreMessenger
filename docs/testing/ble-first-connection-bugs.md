# BLE: ошибки первого подключения к новой ноде

16.10.2026. **Открыто, отложено для последующего исправления.**

[Документация](../README.md) · [Текущий статус](../messenger/plan/current-state.md)

## Контекст проверки

Пользователь подтвердил работу BLE на Heltec V4 с прошивкой 1.17.0.
Heltec V3, также перепрошитая на 1.17.0, тоже работает. Это результаты пользователя,
без новой аппаратной проверки агентом. Предыдущая проблема отсутствия ответа на
первую команду V4/1.16 описана [отдельно](ble-heltec-v4-116.md).

Обнаруженные ниже ошибки относятся к сценарию подключения новой для приложения
ноды по BLE. Не установлено, зависят ли они от транспорта, модели или прошивки;
не считать их автоматически дефектом BLE-библиотеки.

## BUG-CONNECT-01: каналы появляются только после повторного подключения

**Наблюдение пользователя:** при подключении приложения к новой ноде каналы
автоматически не появляются. После повторного подключения каналы отображаются.

**Воспроизведение:** подключить по BLE ранее не использованную в приложении ноду
с настроенными каналами, дождаться завершения подключения и проверить список;
отключиться и подключиться повторно, сравнить результат. Пока не выяснено,
не были ли каналы уже прочитаны и сохранены при первой попытке, но не показаны UI.

**Ожидается:** настроенные каналы появляются после первой успешной синхронизации,
без ручного переподключения.

**Для будущего разбора:** сопоставить SessionId/NodeId, завершение
`DirectoryService.SynchronizeAsync`, фиксацию снимка в БД и обновление проекции UI.
В текущем коде контакты и каналы читаются до сохранения общего снимка; ошибка
чтения оставляет прежний снимок. Проверить порядок переключения ActiveNode/ViewedNode
и публикации результата синхронизации, включая новую ноду без локального кэша.
Причина и связь с BUG-CONNECT-02 пока не установлены.

**Приёмка исправления:** первая сессия с новой нодой показывает её каналы;
смена ноды не показывает чужие каналы; повторное подключение сохраняет результат.
Покрыть установленную причину регрессионным тестом, проверить BLE и сохранение
поведения TCP/Serial без удаления пользовательских данных.

## BUG-CONNECT-02: ошибка чтения сведений о подключённой ноде

**Наблюдение пользователя:** во время проверки появилась ошибка
«Не удалось прочитать сведения о подключенной ноде». Частота, исключение и точное
состояние подключения не записаны; требуются логи при следующем воспроизведении.

**Что проверено по коду:** сообщение с «подключённой» выдаёт catch в
`MainWindowViewModel.ApplyConnectionSnapshotAsync`. Он охватывает не только чтение
ноды, но и применение UI-контекста, сохранение выбора, загрузку истории и запись
последней подключённой ноды. Поэтому текст ошибки сам по себе не доказывает сбой
BLE-команды получения сведений.

`ReadSnapshotNodeAsync` читает локальный репозиторий через `_nodes.GetAsync`,
а не отправляет запрос ноде. В `ApplyConnectionSnapshotAsync` нет отдельного
цикла повторения после исключения: ошибка логируется как
`Could not apply the active node context.`, затем показывается пользователю.
Следующее событие `StateChanged` может снова запустить обработку снимка, но это
не гарантированная повторная попытка обработки неудавшегося состояния.
Retry подключения в `ConnectionSupervisor` — отдельный механизм и не означает
повторение этой UI/локальной операции.

**Для будущего исправления:** получить исходное исключение из лога и определить
упавший шаг; проверить конкурирующие снимки и версии контекста. Решить, нужен ли
ограниченный повтор временного сбоя локального чтения/обновления UI, с отменой при
смене сессии/ноды и завершении приложения. Уточнить текст ошибки по фактической
операции. Не добавлять слепые повторы протокольных команд вместо диагностики.

**Приёмка исправления:** временный воспроизводимый сбой обрабатывается согласно
явной политике восстановления; постоянная ошибка остаётся видимой и диагностируемой;
устаревшая попытка не меняет контекст новой ноды. Отдельно проверить, устраняет ли
исправление BUG-CONNECT-01.

В рамках регистрации багов production-код не изменялся, новая аппаратная проверка
и чтение входящей очереди не выполнялись.
