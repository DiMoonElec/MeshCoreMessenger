# REGION32–34: ручная приёмка и согласованный остаток

17.10.2026. Пользователь проверил приложение после реализации простого поиска
регионов (commit `c192a98`) и предложил зафиксировать REGION32/33 в достигнутом
объёме, затем перейти к REGION34. Это ручной отчёт пользователя; агент в этой
сессии не подключался к ноде и не выполнял новых радиопередач или reboot.

## Подтверждено пользователем

| Сценарий | Результат и граница вывода |
| --- | --- |
| Поиск регионов | Регионы сканируются в текущем GUI |
| Каталог | Регионы добавляются и удаляются; также сообщено «частично удаляются» без отдельной детализации сценария |
| Используемый регион | Приложение не позволяет удалить назначенный регион |
| Сохранение | После перезагрузки регионы не теряются; конкретный вид перезагрузки не уточнён |
| Default | Регион по умолчанию устанавливается |
| Выбор региона канала | Регионы выбираются |
| Отправка | Сообщения отправляются с регионом и без региона |
| ЛС | Не проверялись; не в приоритете, необходима отдельная методика |

Сохранность каталога не объявляется доказательством persistence default во flash
после аппаратного reboot. Из сообщения пользователя не следуют отдельные
readback/capture default до и после, версия прошивки, используемый транспорт,
аварийное завершение, отмена на каждом шаге или проверка доставки каждого сообщения
на другой ноде. Эти сведения не приписываются ручному отчёту.

## Принятое решение и отложенные проверки

REGION32 и REGION33 зафиксированы **в проверенном объёме с отложенной матрицей**.
REGION34 завершает документацию и доступный пользователю сценарий поиска,
каталога/default и выбора scope канала. Полная аппаратная приёмка всех первоначально
предложенных сценариев не заявляется. Указанные ниже пункты не блокируют это
согласованное закрытие и не запускаются автоматически.

| Отложенный пункт | Условие возврата |
| --- | --- |
| ЛС с default, direct/flood, ACK и асимметричные пути | Отдельно согласовать методику, пару нод/получателя, scopes обоих направлений и помеченные сообщения |
| Автономный PATH/ACK во время temporary channel scope | Контролируемый входящий ЛС в этом окне; исследовать как ограничение прошивки, не обещать отсутствие гонки |
| Default GET/SET/CLEAR, точный readback, аппаратный reboot и restore | Согласовать изменение настроек и reboot, сохранить исходную пару name/key, проверить и восстановить её |
| REGION-паритет TCP/Serial/BLE, все платы/firmware | Доступные устройства и транспорты; зафиксировать версии и общий full-key NodeId |
| Crash/разрыв внутри route mutation/cleanup | Отдельный безопасный сценарий с исходным snapshot и проверкой фактического состояния |
| Полная RF-матрица нескольких регионов/направлений/местностей | Согласованные репитеры и принимающая сторона; TX acceptance и RX delivery учитывать отдельно |

Для будущей методики ЛС потребуются отдельная фиксация получения текста и ACK,
исходных маршрутов и default обеих нод, наблюдение повторов/дубликатов, проверка
обратного направления и восстановление настроек. Методика пока не утверждена.

## REGION34: сборка и упаковка

Производственный код после `c192a98` не менялся; тесты выше не запускались заново
ради документационных правок. Выполнен локальный self-contained Release publish
Windows x64 с теми же основными параметрами, что в tools/publish-windows.ps1:

```powershell
dotnet publish src/MeshCoreMessenger.Desktop -c Release -r win-x64 --self-contained true --no-restore --disable-build-servers -m:1 -p:UseSharedCompilation=false -p:UsedAvaloniaProducts= -p:PublishTrimmed=false -p:PublishSingleFile=false -o artifacts/region34win/MeshCoreMessenger -v quiet
```

Команда завершилась успешно, без ошибок и предупреждений. Создан локальный архив
`artifacts/region34win/MeshCoreMessenger-win-x64.zip` (90212236 байт, 317 entries).
Проверены EXE, managed DLL, одна project-owned MeshCoreSharp.dll, coreclr.dll и
Microsoft.WindowsAppRuntime.Insights.Resource.dll внутри архива. SHA256:
`B21ED38057C7A916FE5EE46BFBD2D5AD1208BCFCCB36B1CA9260BEE7C82A2C36`.
Проверены относительные ссылки 14 изменённых/новых Markdown-файлов и git diff --check.
Архив игнорируется git и не включён в документационный коммит.

Это не публикация релиза, не проверка запуска на чистой Windows и не новая
сборка/проверка macOS или Linux.
