# Аппаратный эксперимент: повтор доставки и отправка как новое

Дата отчёта: **05.10.2026**. Испытание провёл пользователь на аппаратных нодах;
результаты, raw-пакеты, SNR и приблизительные интервалы предоставлены пользователем.
Модели/версии прошивок, текст сообщения и абсолютные времена в отчёте не указаны.
Испытывались [два действия контекстного меню](channel-repeat-actions.md).

## Наблюдение в штатном приложении получателя

- **Повторить доставку:** сообщение повторно передано с прежним timestamp;
  в штатном приложении принимающей ноды дубликат сообщения **не появился**.
- **Отправить как новое:** тот же текст передан с новой временной меткой;
  в штатном приложении принимающей ноды появилось **ещё одно сообщение**.
- Пользователь подтвердил: оба действия нашего приложения работают как задумано.

## Пакеты на принимающей ноде

Все пять пакетов имеют header `15`: FLOOD / GRP_TXT. Path descriptor `40`
означает 0 хопов, а `41` — 1 хоп с двухбайтовым path hash репитера `0979`.
Это число ретрансляторов в записанном path, не число всех узлов, слышавших пакет.

| № | SNR, dB | Приём / path | MeshCore packet hash | Содержимое |
| --- | --- | --- | --- | --- |
| 1 | 9.75 | Напрямую, 0 хопов | `AF134BA9BFE83522` | Первая передача |
| 2 | 9.5 | Через `0979`, 1 хоп | `AF134BA9BFE83522` | Payload совпадает с №1 |
| 3 | 10.25 | Повторно напрямую, 0 хопов | `AF134BA9BFE83522` | Полностью совпадает с №1 |
| 4 | 10.25 | Напрямую, 0 хопов | `052B140D081D5A06` | Новый payload |
| 5 | 9.25 | Через `0979`, 1 хоп | `052B140D081D5A06` | Payload совпадает с №4 |

## Временная последовательность по отчёту пользователя

Сначала пакет `AF134BA9BFE83522` принят напрямую (№1), примерно через **4 мс**
пришла его копия через репитер `0979` (№2), ещё через **~0.8 мс** — повторно
напрямую (№3). Примерно через **7 секунд** появился пакет `052B140D081D5A06`
напрямую (№4), а через **~1.5 секунды** — его копия через тот же репитер (№5).

Это приблизительные интервалы из пользовательской расшифровки; исходный журнал
с абсолютными временными метками не приложен, интервалы независимо не проверялись.

## Проверка хешей и вывод

Хеши независимо пересчитаны по предоставленным hex-пакетам: первые 8 байт
`SHA256(payload type || payload)`, payload type = `05`. Header, path descriptor
и байты path в вычисление не включались. Все пять результатов совпали с отчётом.
После удаления path payload у №1–3 одинаковый, у №4–5 одинаковый;
между двумя группами payload различается. Алгоритм:
[Packet.cpp](https://github.com/meshcore-dev/MeshCore/blob/main/src/Packet.cpp).

Приёмник слышал исходного отправителя напрямую и копии через репитер `0979`.
Разный path не изменил идентичность сообщения: №1–3 имеют один packet hash,
№4–5 — другой. Вместе с наблюдением штатного приложения это подтверждает
дедупликацию повтора доставки в условиях данного испытания и повторное появление
текста при «Отправить как новое».

Наличие raw-пакета в журнале означает, что нода слышала передачу, а не что
приложению было выдано ещё одно сообщение. Повторный радиоприём и подавление
дубликата в истории совместимы. В raw payload текст/timestamp зашифрованы:
по hex нельзя независимо прочитать значение timestamp; назначение действий
известно из сценария пользователя, а совпадение/различие пакетов подтверждено хешами.

Этот результат не проверяет поведение после очистки/вытеснения кеша дедупликации,
перезапуска получателя или изменения имени отправителя/ключа канала. Ограничения
и исследование прошивки сохранены в [отчёте эксперимента](channel-repeat-dedup-experiment.md).
