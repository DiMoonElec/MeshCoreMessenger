# Сохранение viewport при подгрузке истории

03.10.2026 · [C10](../messenger/plan/c10-acceptance.md)

Пользователь подтвердил плавность scroll и поиск вне текущего окна, но обнаружил
скачок нижнего сообщения вверх после подгрузки. Пользователь подтвердил повторной
ручной проверкой 03.10.2026: подгрузка вперёд/назад без рывков. Stage D не начат.

## Измерение до исправления

Native Avalonia, активное окно, настоящая временная SQLite; транспорт не запускался.
Первоначальная fixture имела однострочные сообщения. Измерялся Y одного и того же
сообщения, которое было первым видимым перед подгрузкой, относительно history list.

| Сценарий | До → после | Промежуточные advance unread |
| --- | --- | --- |
| Вперёд с обрезкой 500 → 500 | Y = −51; якорь вышел из реализованного диапазона | 1 |
| Вперёд без обрезки 100 → 200 | −51 → −211, отклонение −160 DIP | 0 |
| Назад 100 → 200 | Y = −51; якорь вышел из реализованного диапазона | 0 |

Когда якорь перестал быть реализован, утилита сообщает отсутствие координаты и
infinity как провал критерия, **не** выдуманное численное смещение.

## Исправление

`HistoryScrollIntent` различает `ToMessage`, `ToEnd`, `PreserveViewport`.
Поиск/first unread — целевой переход; latest/live append у конца — переход в конец;
обычный prepend/append — сохранение первого видимого сообщения и его точного Y.

`ViewportChanging` публикуется **до** изменения коллекции: view захватывает anchor
и блокирует viewport/read reports до восстановления. Одноразовые `LayoutUpdated`
callbacks сначала ждут применения новых индексов virtualizing panel, затем реализации
контейнера, восстанавливают `Offset` ровно на разницу текущего/сохранённого Y и ждут
применения layout. Нет таймеров, `Task.Delay`, выбранных вручную поправок или glyph math.
Если variable-height panel ещё не реализовал anchor, новый одноразовый callback ждёт
готовности контейнера; pixel-коррекция не подбирается перебором.

В Avalonia 12.1.3 `ScrollIntoView` может выполнять вложенные layout/BringIntoView
проходы: восстановление подписывается **после** его возврата, иначе финальный проход
перезаписывает смещение. Проверено по [исходнику текущей версии Avalonia](https://github.com/AvaloniaUI/Avalonia/blob/12.1.3/src/Avalonia.Controls/VirtualizingStackPanel.cs).
Смена context, скрытие и detach отменяют callbacks; есть отдельная revision scroll
request и проверки node/conversation ownership.

## Измерение после исправления

Fixture усилена многострочным текстом/emoji/mentions разной высоты; backward
проверяется возле верхнего края. Light и Dark дают одинаковые результаты:

| Сценарий | Y до → после | Отклонение | Advance unread |
| --- | --- | --- | --- |
| Вперёд с обрезкой 500 → 500 | −52,5 → −52,5 | 0 DIP | 0 |
| Вперёд без обрезки 100 → 200 | −52,5 → −52,5 | 0 DIP | 0 |
| Назад 100 → 200 | −45 → −45 | 0 DIP | 0 |

Критерий — ≤1 логического pixel/DIP. Нулевое отклонение также нулевое при Retina
scaling. Проверка считает все обращения к fake read store, а не только конечный
unread count: промежуточная ошибочная запись не скрывается восстановлением UI.

Воспроизводимый native executable:

```sh
dotnet run --project tools/MeshCoreMessenger.ViewportAudit -c Release
```

По умолчанию нарушение критерия возвращает ошибку; `--measure-only` только печатает
результат. Нужна desktop/display session, это не headless unit test. Fixture создаётся
в отдельной временной папке, реальные подключения и стандартные данные не затрагиваются.
Подготовка позиции изолирована от самого измерения; подробности — README утилиты.

Headless test проверяет порядок prepare → collection changes → scroll request,
лимит 500 и намерения; прежние tests сохраняют search/latest, unread и context guards.
Core, schema, протокол и MainWindowViewModel не менялись.

Изменены `HistoryWindowViewModel`, `ConversationView.axaml.cs`, history unit tests
и fixture-фабрика UI integration tests. Добавлены `NativeViewportAudit.cs` и
отдельный developer executable `tools/MeshCoreMessenger.ViewportAudit` с lock file;
он не входит в production startup или headless discovery. Native audit также
подтверждает отмену pending restoration при скрытии чата.

Debug/Release solution build без предупреждений/ошибок. Desktop 243/243 в обеих
конфигурациях, Release Core 131/131, MeshCoreSharp 92/92; native audit прошёл все
шесть случаев. `git diff --check` чистый. Это автоматическая приёмка исправления,
Ручная проверка подгрузки вперёд/назад также подтверждена пользователем.

Один финальный повтор Release suite не завершился за пять минут и был остановлен;
последовательный повтор с `-longRunning 30` прошёл 243/243 за 15,4 с. Причина
единичного зависания не установлена; успешный повтор не считается её исправлением.

Ручная проверка: в большой fixture пройти вперёд через несколько обрезок окна,
затем назад; прежнее первое видимое сообщение остаётся на той же высоте. Повторить
с многострочными сообщениями, поиском, «к последнему», first unread и сменой вкладки.
