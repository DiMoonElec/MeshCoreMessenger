# Очистка переписки и истории успешных доставок

05.10.2026. По запросу пользователя прежняя retention после явного clear отменена.
Приватная очистка удаляет ContactDeliveryHistory строго по NodeId и полному
32-байтовому ContactPublicKey из проверенной Conversations. Префикс контакта,
имя, MessageId и выбранный UI после подтверждения не используются как фильтр.
Включены прежние записи с MessageId=NULL. Evidence, candidates и оба вида снимков
маршрута удаляются FK cascade в той же транзакции, что сообщения и read watermark.
Timestamp floor, текущая конфигурация контакта/маршрут и черновик сохраняются.
Схема БД не меняется; публичная очистка не удаляет аналитику контактов.

GetStatus сообщает наличие аналитики, поэтому меню очистки доступно даже для
переписки без сообщений, если остались старые delivery records. Guard/pending send
и запрет очистки при persistence pause сохранены. Текст подтверждения включает
историю успешных доставок. После повторного открытия карточки контакта таблица пуста.

Отложенный readback использует UPDATE: удалённые записи он не создаёт заново.
Поздний ACK после clear не находит удалённую attempt и не восстанавливает историю.
Обычное удаление контакта/переписки без явной очистки сохраняет прежнюю nullable
retention; это отдельное действие.

Проверено на SQLite:

- действительное ACK success и learned route удаляются вместе с сообщением;
- другой контакт с тем же 6-байтовым префиксом сохраняет всю аналитику;
- тот же полный ключ на другой ноде сохраняет всю аналитику;
- неверная node/conversation pair отклоняется до удаления;
- очистка публичного чата не затрагивает ни одного contact delivery;
- записи без MessageId удаляются, пустая переписка с аналитикой доступна для clear;
- ошибка UPDATE watermark откатывает удаление всех трёх аналитических таблиц;
- поздние ACK/readback не восстанавливают записи, reopening подтверждает удаление;
- прежние regression tests атомарной очистки сообщений/attempts и isolation проходят.
