# P3 — общий ACK commit и история доставок

05.10.2026. [План](../messenger/plan/d7-private-auto-retry.md).
Предыдущая часть P2 закоммичена как `32291ce`.

## Результат

Raw session ACK, результат библиотечного waiter и прямая Delivered transition
проходят одно сопоставление в SQLite. Все совпадения NodeId/SessionId/tag,
включая завершённые попытки, группируются по MessageId. Несколько сообщений —
коллизия, ни одно не выбирается. Несколько попыток одного сообщения подтверждают
общий цикл с MultipleCandidates attribution; их состояния/успешный маршрут не
угадываются. Уникальная captured попытка даёт SingleAttempt, legacy — Unknown.

Итог цикла, первый ContactDeliveryHistory, evidence и снимки кандидатов сохраняются
в одной транзакции. Ошибка любой записи откатывает весь результат. Повтор ACK/
writer retry не создаёт второй успех и не заменяет первое время/RTT. Новый ACK
другой попытки добавляет evidence с её сетевой идентичностью и маршрутом. На
данном этапе фактические PcSent поля могут быть NULL: они заполняются coordinator
в P4. Время подготовки не выдаётся за реальное время передачи.

Последняя Unconfirmed при исчерпанном бюджете завершает цикл; Failed/Unknown
останавливают его. Delivered имеет приоритет над поздними timeout/cleanup. Поздний
ACK первой фазы может подтвердить цикл во время fallback; новые prepare запрещены.
Присваивание итогового Delivered не зависит от того, какая attempt была последней.

ACK admission использует порядок writer, без ReceivedUtc >= StartedUtc. При
незарегистрированном MSG_SENT любой private Sending текущей session ACK временно
буферизуется, даже если ранее записанный tag совпал. После регистрации всех тегов
проверяется коллизия. ACK до начала Sending без совпадения не сохраняется для
будущей передачи. Истинное AckReceivedUtc/offset/timezone записывается отдельно от
технического CompletedUtc, который сохраняет старые CHECK constraints.

Known-tag Unknown может подтвердиться поздним ACK. Исключение — Unknown с
MeshCoreProtocolException: библиотечная коллизия может оставить второй MSG_SENT
недоступным Core, поэтому такой protocol fault нельзя объявлять уникальным успехом.
Сами библиотечные правила duplicate-tag/window/subscribe-before-send не изменены.

## Проверки

Release solution build: **0 warnings/errors**; библиотека **105/105**, Core
**312/312**, Desktop **315/315**. Девять новых регрессий:

- ACK known/T1 при начатом fallback/T2 подтверждает общий цикл и маршрут T1.
  Добавочный ACK T2 создаёт второе evidence, сохраняя первый delivery result.
- Два совпадающих тега одного MessageId подтверждают цикл с двумя кандидатами;
  отдельные попытки остаются Unconfirmed, следующий prepare запрещён.
- Cross-message collision нельзя обойти прямой Delivered transition или двумя
  библиотечными waiter Confirmed.
- После исчерпания бюджета поздний ACK подтверждает доставку; часы ПК переведены
  назад. uint.MaxValue RTT сохраняется в evidence. Инъекция ошибки history INSERT
  откатывает Delivered; durable Retry/Flush повторяет только SQLite. Очистка
  переписки сохраняет аналитические снимки без ссылок на удалённые сообщения.
- Совпавший старый tag ждёт MSG_SENT другой Sending и затем безопасно распознаётся
  как коллизия; без этого происходило бы преждевременное подтверждение.
- Known-tag cleanup Unknown подтверждается поздним ACK.
- Тайм-аут более новой попытки не отменяет Delivered, установленный ACK старой.
- Ранний ACK при переводе часов назад ждёт Accepted commit, timeout не стирает успех.

Сохранены существующие TCP-эмуляционные регрессии late/reverse ACK, duplicate-tag
fault, очистки до ACK и persistence pause/retry. Старый тест «время ACK раньше
StartedUtc» обновлён: такое время допустимо при переводе часов ПК назад. Проверка
завершённой попытки при последующей коллизии подтверждает первую до регистрации
второй: прямой Delivered после уже известной коллизии теперь правильно запрещён.

Аппаратная нода не использовалась. P3 не включает автоматические передачи;
следующий P4 добавляет session-owned coordinator и ограниченную очередь контакта.
Общие UI projections и чтение аналитики остаются отдельными P6/P7.
