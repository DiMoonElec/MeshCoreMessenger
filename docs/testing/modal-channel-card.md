# Карточка публичного канала

Реализовано 04.10.2026 на существующем modal host; в Public menu «Подробности (тест)»
заменён на «О канале». Private menu сохраняет «О контакте». Команда и обработчик
назначаются при инициализации workspace. Общее имя `DetailsCommand` используется
обоими видами чатов, состав остальных пунктов не меняется.

## Доступные сведения

Существующий `ChannelDetailsProjection` уже содержит всё для read-only карточки:

- Название — первое поле, с тем же оформлением, что имя в карточке контакта.
- Тип доступа: публичный/hashtag, общий секрет либо неизвестный. Название само по
  себе не считается доказательством типа доступа.
- Наличие канала в актуальной локальной конфигурации ноды.
- Все активные слоты (с исходной нумерацией Companion, включая слот 0).
- Даты создания и обновления локальной записи. Это не дата создания mesh-чата.
- Полный SHA-256 отпечаток ключа; он не является секретным ключом канала.

Несколько слотов могут соответствовать одному каналу. Канал идентифицируется
NodeId + отпечатком ключа, а не названием/слотом. Отсутствие активных слотов
отображается как локально сохранённый канал, который сейчас не настроен на ноде.
Это не свидетельствует о существовании или отсутствии других участников.

В текущих projections отсутствуют список участников, число подписчиков и
состояние доставки для канала в целом; карточка их не вычисляет. Поле секрета
в read API отсутствует. Статистика истории могла бы быть отдельным расширением
read projection, но в эту карточку не включена.

Данные читаются заново при каждом открытии через `IConversationDirectoryReader`.
Не выполняются радио-запросы, изменения конфигурации, истории или схемы БД.
Карточка доступна offline для известных каналов, включая локальную историю без
активных слотов. Для неразрешённых `UnknownChannel` подробности недоступны:
opaque identity такой переписки нельзя выдавать за отпечаток ключа.

Выбор канала захватывается при клике; смена собственной ноды не переадресует уже
открытую карточку. При ошибке доступен повтор чтения. Закрытие отменяет чтение;
поздний результат после закрытия игнорируется. Метаданные повторно читаются при
следующем открытии, непрерывная подписка на изменения каналов пока не нужна.

## Проверки

- Release Desktop: 313/313 тестов.
- Новые сценарии: чтение свежих метаданных из временной SQLite, несколько слотов,
  одинаковый отпечаток на разных собственных нодах, offline, сохранённый канал
  без активных слотов, отсутствующие сведения/ошибка и повтор, отмена с поздним результатом.
- Native `--modal-only`: Contact/Channel × Light/Dark × 420/960 — 8 сочетаний,
  проверены шаблон содержимого, границы карточки/resize, блокировка основного UI,
  Tab/Shift+Tab, Esc, крестик и возврат фокуса.
- Только fake supervisor и временная БД, без аппаратной ноды.

```sh
dotnet run --project tests/MeshCoreMessenger.Desktop.Tests -c Release
dotnet run --project tools/MeshCoreMessenger.ViewportAudit -c Release -- --modal-only
```

Изображения: `$TMPDIR/meshcore-modal-cards/channel-{Light|Dark}-{420|960}.png`.
Пользователь подтвердил ручную приёмку карточки канала 04.10.2026.

Заголовок Public переписки теперь содержит только название; дополнительные
сведения доступны в этой карточке. Native `--modal-only` проверяет, что строка
метаданных в Public скрыта, а в Private содержит только `Маршрут: …`.
